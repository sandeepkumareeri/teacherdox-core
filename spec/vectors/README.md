# `.tdx` 2.0 test vectors

Conformance vectors for implementations of the `.tdx` 2.0 record ([spec §10](../tdx-2.0.md#10-test-vectors)).
Generated by [`scripts/make-vectors.js`](../../scripts/make-vectors.js); deterministic — regenerating gives
byte-identical files, and `npm test` checks every expectation against both implementations in this repository.

| File | Cases | Check |
|---|---|---|
| `keys.json` | — | The test key: **its seed is public, so it proves nothing — never use it for real records.** `registries` holds the key registry variants the cases refer to by name (`default`, `empty`, `revoked`, `expired`, `future`). |
| `canonical.json` | 6 | `JCS(input) == canonical` and `sha256(canonical) == sha256` (RFC 8785: key order by UTF-16 code units, ECMAScript number form, escapes). |
| `capsules.json` | 15 | Verify `capsule` against `registries[registry]`. Valid: `signing_input` and `capsule_hash` match exactly. Invalid: verification fails with exactly the `codes` listed ([spec §9](../tdx-2.0.md#9-verification-failure-codes)). |
| `days.json` | 11 | Verify all `capsules` as one educator-day: contiguous sequence from 0, `prev_hash` links, amendments; `effective` = the record per entry that no other record amends. |
| `merkle.json` | 5 trees, 4 seals | Merkle roots and every inclusion proof for 1, 2, 3, 5 and 7 leaves; day seals over the given capsule hashes. |
| `countersignatures.json` | 5 | Verify a countersignature against its `target` (a locked capsule or a day seal). |

Ids, times and the key are fixed; Ed25519 signatures are deterministic (RFC 8032), so your implementation
should reproduce the signatures in the valid cases byte for byte when signing the same input with the test key.
